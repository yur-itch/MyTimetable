MyTimetable берёт вузовское расписание ТГУ (intime.tsu.ru API) и показывает его. Готова часть с вузовским расписанием: CacheWorker раз в минуту тянет API, рендерит Razor → Brotli → синглтон ScheduleData, фолбэк на Postgres.

Следующий этап (на 2026-06-24 ещё не начат): планировщик своих пар с инвалидацией пар, пересёкшихся с вузовским расписанием. «Свои пары» — это блоки времени на самообучение бэку на след. учебный год (проект рекурсивный: учит бэк, строя планировщик обучения бэку). Замысел: LLM-ка анализирует заметки и прогресс по темам/проектам и решает ЧТО изучать (выбирает предмет + в фоне готовит тезисную разбивку), а планировщик решает КОГДА — расставляет в свободные будущие слоты на ~2 недели вперёд, при коллизии переставляет свою пару в будущее, вузовскую не трогает.

Архитектурные решения/советы, проговоренные в ревью:
- Строить планировщик за интерфейсом источника пар (IStudyPlanSource) на «тупом» источнике сначала, LLM подключить позже — развязка и тестируемость.
- Контракт LLM↔планировщик: LLM эмитит «учебные единицы» (предмет + оценка кол-ва сессий + приоритет), планировщик только размещает. Кто решает число/длину сессий — точка связи.
- Модель данных-развилка: (а) одна таблица + IsCustom-дискриминатор + тройной PK (Date, LessonNumber, IsCustom), self-join для коллизий — проще пока полей мало; (б) две таблицы (UniversityLesson, StudySession) — чище когда своя пара обрастёт полями (FK на тему, тезисы, статус done/skip).
- Сигнал о прогрессе (как фиксируется «освоил/не успел») — узкое место качества LLM, проектировать рано.
- Перф-цель (по фану): главная страница должна влезать в первое окно перегрузки TCP — ~14 KB в сжатом (Brotli) виде, чтобы приходить за 1 RTT данных. Сейчас ~12 KB на весь год (структура жмётся отлично). Следствие: уникальный текст (тезисы от LLM, заметки) НЕ инлайнить в главную — он жмётся плохо и пробьёт бюджет; грузить лениво через GetOne/fetch по прогретому окну. Замечено в ревью: редирект `/`→`/app` (AppController.Root, 302) стоит лишнего RTT — отдавать HTML прямо на `/`.
- При интеграции LLM — структурированный вывод (tool use / JSON-схема). Провайдер пока не выбран.

Известные правки в ходе ревью: 6-слот guard и слот-6 в GetOne пользователь починил; фикс профессора был неполный (`?.` нужен, а не `??`); статус-код ответа API ещё не проверяется; пароль БД в appsettings.json в гите. См. [[user-profile]].
