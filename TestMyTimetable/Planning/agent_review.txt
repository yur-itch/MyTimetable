 1. GapClosingSelector.cs — file naming inconsistency: should be
    GapClosingSelectorTests.cs (missing "Tests" suffix, unlike every other
    file).

 2. Unused Moq dependency — Moq is referenced in .csproj but no test file
    actually uses it. The CompositePlanningSelectorTests rolls its own
    hand-written SimpleSelector/SimpleFactory test doubles instead. Either
    remove Moq or use it (probably worth keeping for future integration
    tests).

 3. RoundRobinPicker tests simulate caller decrement — they manually do
    q["A"]-- after each Pick(). This leaks the implementation contract into
    tests: if Plan() changes its decrement strategy, these tests won't catch
    it. Better to test through the full RoundRobinSelector.Plan() which
    already does.

 4. No test for DayLayout.GetDays edge case with unsorted input — there's a
    test GetDays_SlotsOutOfDateOrder_StillGroupsByAdjacentDates that
    documents "does not sort," but there's no test verifying the behavior
    when slots within a single date are out of Number order (e.g., slot 5
    then slot 2 on the same date).

 5. GapClosingSelector tests use reflection to invoke GetGapsInDay (a private
     method). This is fragile — renaming the method breaks tests with no
    compile error, only a runtime InvalidOperationException. Consider making
    it internal + InternalsVisibleTo, or test through Plan().
